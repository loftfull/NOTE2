# Проверка AI-функций на реальных примерах

Здесь два файла: сервер-стенд и прогон всех AI-действий приложения.

## Против настоящей модели

Это главный сценарий. Стенд не нужен — прогон идёт через тот же слой, которым
пользуется интерфейс:

```bash
node tools/model-conformance/check.mjs \
  --base https://openrouter.ai/api/v1 \
  --model deepseek/deepseek-r1:free \
  --key sk-or-ВАШ_КЛЮЧ
```

Выведет все девять действий с настоящими ответами и временем каждого. По ним
видно и правильность запроса, и качество модели.

Для локальной модели ключ не нужен:

```bash
node tools/model-conformance/check.mjs --base http://localhost:11434/v1 --model qwen2.5:7b
```

## Против стенда, когда модели нет

```bash
node tools/model-conformance/server.mjs --port 8799 --mode ok &
node tools/model-conformance/check.mjs --base http://127.0.0.1:8799/v1 --model conformance/echo-free
```

Стенд отвечает отчётом о том, что ему прислали: модель, системная инструкция,
число реплик, длина запроса. Текст ответа намеренно начинается с `[СТЕНД]`,
чтобы его нельзя было принять за ответ настоящей модели ни в интерфейсе, ни на
скриншоте.

### Режимы отказа

Качество модели без модели не проверить. Но почти всё, что ломается на
практике, — не качество, а поведение приложения, когда провайдер отвечает не
тем. Эти режимы и надо уметь пережить:

| `--mode` | Что изображает |
|---|---|
| `ok` | обычный ответ |
| `empty` | модель вернула пустой текст |
| `html` | HTML вместо JSON: прокси или страница входа |
| `401` | неверный ключ |
| `429` | превышен лимит, с `Retry-After` |
| `500` | ошибка на стороне провайдера |
| `slow` | ответ дольше таймаута приложения |

## Что показал прогон 2026-09-26

Приложение переживает все режимы, ни в одном не выдавая выдуманного ответа:

```
empty → ⚠️ AI недоступен. Модель вернула пустой ответ.
html  → ⚠️ AI недоступен. Ответ не JSON (200, text/html). Проверьте адрес.
401   → ⚠️ AI недоступен. Incorrect API key provided.
429   → ⚠️ AI недоступен. Rate limit exceeded
500   → ⚠️ AI недоступен. Upstream model unavailable
slow  → ⚠️ AI недоступен. Превышено время ожидания модели.   (через 60 с)
```

Два дефекта найдены именно прогоном, а не чтением кода, — оба исправлены:

1. **Все действия слали одинаковый запрос.** `action` принимался и не
   использовался на прямом пути к провайдеру: «Сводка», «Улучшить»,
   «Ключевые слова» и «Название» отправляли байт в байт одно и то же, и модель
   не могла знать, чего от неё хотят. Инструкции вынесены в `src/ai-actions.js`
   и теперь общие для прямого пути и пути через шлюз.
2. **Вопрос уходил модели дважды.** Экран разговора передавал историю вместе с
   только что заданным вопросом, а он добавляется отдельно: пять сообщений там,
   где должно быть четыре.

**Не проверено: качество ответов настоящей модели.** В окружении, где это
писалось, сетевая политика закрывает все провайдеры (`openrouter.ai`,
`api.openai.com`, `api.groq.com` и прочие отвечают `000`), а два отвечающих
отвергают доступные учётные данные. Локального рантайма моделей нет, веса
скачать неоткуда. Поэтому проверена правильность запросов и поведение
приложения — но не то, насколько хорош ответ. Это делается одной командой выше,
у кого есть ключ.
