# Проверки в браузере

То, что нельзя проверить без настоящего движка: импорт файлов через
интерфейс, контраст на отрисованной странице и движение.

`node --test` их не запускает: нужен Playwright и браузер, а они в
зависимости проекта не входят.

```
npm i --no-save playwright
npm run build
node tools/e2e/import.mjs          # добавление файлов через интерфейс
node tools/e2e/palette-check.mjs   # контраст по WCAG на пяти экранах
node tools/e2e/motion.mjs          # отклик, переходы, prefers-reduced-motion
```

Первый аргумент — каталог сборки (по умолчанию `dist`). У `import.mjs`
второй аргумент — каталог с файлами (по умолчанию `test/fixtures/files`).

Браузер ищется так: переменная `NOTE2_CHROMIUM`, затем предустановленный
Chromium контейнера, затем тот, что найдёт Playwright сам.

## Что именно проверяет каждый

**`import.mjs`** открывает лист быстрого добавления, выбирает все файлы
набора и читает то, что реально записано в IndexedDB, а не то, что
нарисовано на экране. Печатает по каждому источнику вид, статус, число
слов, секций и страниц. Здесь же проверяется PDF — в `node --test` он
недоступен: `src/pdf-text.js` подключает воркер pdfjs импортом с `?url`,
который понимает только сборщик.

**`palette-check.mjs`** обходит пять экранов и для каждой пары
«текст на фоне» берёт фактический цвет текста и фактический фон под ним,
смешивая полупрозрачные слои вверх по дереву. Порог AA выбирается по
размеру и весу шрифта (крупным считается ≥24px или ≥18.66px при весе
≥700). Выходит с кодом 1, если хоть одна пара ниже порога.

**`motion.mjs`** нажимает мышью на пять целей и снимает `transform` во
время нажатия — так ловятся ошибки каскада, которые чтением CSS не
видны. Заодно сверяет положение фиксированных элементов до и после
нажатия: любой `transform`, кроме `none`, делает элемент containing block
для `position: fixed` внутри. Прогоняется дважды — обычно и с
`prefers-reduced-motion: reduce`.

Каждую цель скрипт жмёт на свежей загрузке: нажатие на настоящую кнопку
уводит с экрана, и следующая цель исчезает.
