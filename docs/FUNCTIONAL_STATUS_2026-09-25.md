## Правило, которое соблюдается во всех маршрутах модели

Ненастроенная возможность отвечает **503 и называет переменную**, которая её
включит. Она не возвращает ни `output`, ни `text`, ни `vectors`. Локально
извлечённый текст, отданный отсюда, дошёл бы до клиента с пометкой
`origin: 'model'` и был бы неотличим от настоящего анализа — это единственный
вид отказа, который ниже по течению обнаружить нечем.

Отдельный тест проверяет все четыре маршрута сразу и падает, если хоть один
вернёт текст без настроенной модели.

## Оговорки — что я НЕ проверял

1. **YouTube против живого сайта.** Сетевая политика этого окружения запрещает
   CONNECT к `www.youtube.com` (в логе прокси: `gateway answered 403 to
   CONNECT`). Разбор проверен на заглушке страницы. Нужно подтвердить, что
   страница видео по-прежнему содержит `captionTracks` в том виде, который
   ожидает `media-connectors.mjs`.
2. **Живые модели.** Все маршруты моделей проверены против мок-провайдера,
   который записывает присланное. Настоящих OpenAI, Ollama или Whisper я не
   вызывал — ключей в окружении нет.
3. **Instagram.** Мост проверен полностью: запуск команды, таймаут, ненулевой
   код возврата, отказ до запуска на не-Instagram ссылке. Самого сборщика
   репозиторий не содержит и не обходит ограничения площадки.
4. **Устройства не было.** safe-area, Share Target, Keystore подтверждены
   только кодом.
5. **Миграции IndexedDB v1→v3 теперь покрыты тестами** (`test/source-db.test.mjs`,
   12 тестов на `fake-indexeddb`): база создаётся в старой версии с данными,
   затем открывается модулем, и проверяется, что строки пережили обновление.
   Проверено, что тесты ловят дефект: три мутации кода дают красные тесты.
   На реальных старых данных пользователя по-прежнему не проверялось.
   `source-db.js`, `source-index.js`, `job-core.js` и `instagram-analysis.js`
   остаются реконструкцией по контрактам вызовов, а не оригиналами.

## Android

Каталог `android/` создан, `scripts/prepare-android.mjs` написан заново.
`applicationId` — `app.noteai.workspace`, не менялся.

`npm run android:prepare` собирает клиент, создаёт проект, если его нет,
синхронизирует ресурсы и делает две вещи, которых `cap add android` не делает:
добавляет в launcher-activity intent-filter для приёма из share-меню (без них
приложение просто не появляется в списке «Поделиться», и `src/share-target.js`
ждёт события, которое не может произойти) и отказывается продолжать, если
package id разошёлся с `capacitor.config.json`. Повторный запуск — no-op,
проверено.

**APK в этом окружении собрать нельзя, и причина конкретная.** Android Gradle
Plugin отдаётся с `dl.google.com`, а прокси здесь отвечает 403:

```
Could not GET 'https://dl.google.com/dl/android/maven2/com/android/tools/
build/gradle/8.13.0/gradle-8.13.0.pom'.
Received status code 403 from server: Forbidden
```

Плюс в окружении нет Android SDK и `sdkmanager`. На машине, где есть и то и
другое, следующий шаг — `cd android && ./gradlew assembleDebug`.

**Покрытие клиента.** 275 тестов. Исходные 39 тестов приложения утрачены, но
закрыты: слой данных (миграции и транзакционность хранилища), разбор PDF,
русский стемминг поиска, история запросов, фильтры источников. Без покрытия
остаются React-компоненты: они проверяются прогонами в браузере, а не тестами.

## Безопасность

`pdfjs-dist` был версии 5.7.284 — в диапазоне GHSA-hq66-cqwq-w95j
(выполнение произвольного JavaScript при открытии вредоносного PDF,
высокая серьёзность). Приложение принимает PDF от пользователя, то есть путь
эксплуатации прямой. Обновлено до 6.3.289.

Мажорное обновление проверено, а не принято на веру: стенд
`tools/pdf-probe` собирает `src/pdf-text.js` так же, как его собирает
приложение, и вызывает в настоящем браузере. Вывод до и после совпал
побайтово.

Осталось 3 уязвимости средней серьёзности — все в цепочке зависимостей
`@capacitor/cli` (`uuid` через `xcode`). Это сборочный инструмент, в
приложение не попадает.
