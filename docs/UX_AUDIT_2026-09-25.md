# Пользовательский аудит — 2026-09-25

Продолжение `UX_AUDIT_2026-09-15.md`. Тот аудит закончился списком из шести
нерешённых пунктов. Здесь — что из них закрыто, чем это подтверждено и что
осталось.

Все замеры сделаны в Chromium на собранном бандле, который отдаёт сам шлюз,
390×844, с реальными данными.

---

## Главная находка: в приложении 10 экранов и 5 пунктов навигации

Три экрана были недостижимы. Не скрыты и не помечены устаревшими — на них не
вела ни одна ссылка во всём коде:

```
grep -on "go('studio')\|navigate('studio')"   src/App.jsx → пусто
grep -on "go('graph')\|navigate('graph')"     src/App.jsx → пусто
grep -on "go('youtube')\|navigate('youtube')" src/App.jsx → пусто
```

Самый показательный — YouTube: у функции был маршрут на сервере, клиентский
модуль и готовый экран, и не было двери. Это и есть значительная часть того,
что на практике означает «мало функционала»: функциональность написана и до
неё нельзя дойти.

**Что сделано.** Навигацию не расширяли до десяти пунктов. Три экрана, которые
строятся из одних данных — заметки, их теги, задачи — стали видами одного
раздела «Заметки». Два, которые по сути являются способами что-то добавить,
встали в меню «+» рядом с «Документом» и «Аудио».

Маршруты `/tasks` и `/graph` сохранены и открывают нужный вид, поэтому ссылка
«Все задачи» с главной продолжает работать, а не ломается молча.

Замер до правок:

| блок | высота |

| Данные и хранилище | 371 |
| **`.page` целиком** | **3787 px = 4,5 экрана** |

Четыре блока из семи — настройки сервера: 2489 px, 67% экрана, в приложении
для личных заметок.

Ничего не удалено: запрет на удаление работающего функционала прямой. Каждый
блок свёрнут в `<details>` и, пока закрыт, показывает своё состояние строкой
вместо пустых полей:

```
Свой сервер-шлюз          Подключено: YouTube
Аккаунт и устройства      Вход не выполнен — заметки только на этом устройстве
Данные и резервные копии  3 заметки, 2 задачи на этом устройстве
```

**После: 1667 px = 2,0 экрана.** Той же метрикой. Все поля и кнопки на месте,
клавиатура доходит до заголовков, состояние озвучивается скринридером —
`<details>`/`<summary>`, а не `div` с обработчиком клика.

## Поиск: найден настоящий дефект

Браузерный тест, написанный для проверки другого, показал: запрос **«хлеб» не
находил заметку «Рецепт хлеба»**. Сравнение шло по словоформам буквально, и
любое склонение разрывало совпадение. Для русского это не краевой случай.

Подключён стеммер Snowball (`src/stem-ru.js`). После:

```
«хлеб»     → 1 результат  · Рецепт хлеба      (было 0)
«книгами»  → 1 результат  · Книги на год
«рецептов» → 2 результата · Рецепт хлеба, Книги на год
```

Стемминг применяется только для сопоставления. `tokenize()` не тронут: его
результат показывают человеку тегами, и «#заметк» вместо «#заметки» читается
как поломка.

Пустой экран поиска теперь показывает недавние запросы (сохраняются, переживают
перезагрузку), реальные теги из заметок и охват поиска. Переключатель
«Гибридный» переименован в «По смыслу» и честно сообщает, что без модели с
ролью «векторный поиск» он совпадает по словам.

счётчика фрагментов.

## Что осталось

1. **Быстрые действия на главной** по-прежнему дублируют меню «+» и вкладку
   «Поиск». Это решение о продукте, а не дефект: убрать их или наполнить тем,
   чего нет в один тап рядом.
2. **Кнопка импорта в «Источниках»** — безымянная иконка в шапке, при том что
   пустое состояние прямо просит добавить файл.
3. **Фильтры источников** стоит показывать по возможностям шлюза: Instagram
   без внешнего сборщика подключить нечем, и фильтр для него — обещание без
   покрытия.
4. **Экран «Источники» — 342 px** при пустой библиотеке. Самый бедный из
   оставшихся.
5. **Дизайн как таковой** — оценка владельца 3/10 — в этом проходе не
   менялся. Здесь правились структура, доступность экранов и язык; цвет,
   типографика и пластика стекла остались прежними.
