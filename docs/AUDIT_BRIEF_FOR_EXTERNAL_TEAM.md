## 2. Честная история проекта (важно, читать до планирования)

Без этого контекста ты потратишь дни на поиск кода, которого нет.

1. **Приложение никогда полностью не лежало в этом репозитории.** Исходники
   версии v4.10 пытались загрузить четырьмя разными способами; ни одна попытка
   не была доведена до конца.
2. **48 файлов восстановлены** из оборванной base64-загрузки скриптом
   `tools/recover-v410-source.mjs` с проверкой CRC-32 по каждому файлу. Два
   файла CRC не прошли и отброшены. Скрипт детерминированный, его можно
   перезапустить и проверить.
3. **Результат восстановления не совпадает с SHA-256 в `note2-source.lock.json`** —
   то есть это заведомо неполный слепок, а не оригинал целиком.
4. **Утрачено безвозвратно:**
   - `server.mjs` — Node-шлюз, на котором держалась половина функционала;
   - каталог `android/` и `scripts/prepare-android.mjs`;
   - исходный набор из 39 тестов;
   - release gate (`npm run release:gate`, `release:windows` — таких скриптов
     не существует ни в каком виде).
5. **Четыре модуля — не оригиналы, а реконструкция по контрактам вызовов:**
   `src/source-db.js`, `src/source-index.js`, `src/job-core.js`,
   `src/instagram-analysis.js`. Они восстановлены по тому, как их вызывает
   `App.jsx`. Поведение может отличаться от исходного. Миграции IndexedDB
   v1→v3 на реальных старых данных **не проверялись**.

Что из этого следует для тебя: **`npm start` не работает** — в `package.json`
есть `"start": "node server.mjs"`, а самого файла нет. Это не баг сборки, это
последствие пункта 4.

## 4. Приоритеты. Начинай отсюда

Порядок не случайный: сверху то, что даёт больше всего функционала за единицу
работы.

### P0 — `server.mjs`

**Один модуль закрывает шесть функций сразу.** Контракт известен: клиент уже
знает, какие эндпоинты и какие формы ответов ему нужны. Извлеки контракт из
мест вызова:

```bash
grep -rn "/api/" src/ *.mjs
```

Требования:
- защита от SSRF в `/api/source-url` — она была серверной, в клиенте её нет;
- лимиты на размер загрузки и на время обработки;
- честные коды ошибок: если внешний сервис недоступен, это HTTP-ошибка с
  текстом, а не подделанный успешный ответ;
- запуск одной командой, задокументированной в README;
- тесты на каждый эндпоинт.

### P1 — Android

`capacitor.config.json` и зависимости (`@capacitor/core`, `@capacitor/android`,
`@capgo/capacitor-share-target`) на месте. Нужны генерация проекта, сборка
debug APK и проверка на устройстве. **Package id менять нельзя.**

### P2 — Интерфейс и продуктовая логика

Владелец оценил дизайн в 1–3 из 10 в нескольких итерациях. Претензии, которые
он высказывал дословно: «некрасиво, статично и скучно», «уродские цвета,
уродская форма смотрится как использованная туалетная бумага», «нет очевидной
логики, дубль функций, слабость функционала».

Что он хочет: интерактивность, анимации, **glassmorphism** в дорогих
цветовых сочетаниях, уровень лучших сайтов и приложений категории.
Ориентиры, которые он присылал: брендинг Claude (плавающая pill-навигация на
тёплом кремовом фоне), glassmorphism-дашборды с яркими цветными плитками
иконок.

Разбор текущей главной и десять альтернативных концепций — в
`docs/UX_AUDIT_2026-09-15.md`. Оттуда же нерешённые вопросы:

1. четыре «быстрых действия» на главной дублируют шторку «+» и вкладку «Поиск»;
2. задачи показаны на главной, но вкладки задач в навигации нет;
3. экран поиска — пустое поле без истории, подсказок и примеров;
4. кнопка импорта в «Источниках» — безымянная иконка, при том что пустое
   состояние прямо просит добавить файл;
5. фильтры Instagram / YouTube / Веб видны, хотя подключить их нечем;
6. заголовок раздела выводится дважды — в липкой шапке и в теле — на всех
   пяти экранах.

Проверять на ширинах **360×800, 390×844, 430×910, 1440×900**. Ноль
горизонтальных переполнений, ноль ошибок в консоли.

### P3 — Тесты и качество

Сейчас 50 тестов (`node --test`), файлы: `test/ai-fail-closed.test.mjs`,
`test/archive-bomb.test.mjs`, `test/gateway-endpoint.test.mjs`,

покрытия заметок, источников, поиска и миграций IndexedDB нет.

## 6. Как отчитываться

На каждый дефект:

```
ID | Severity (P0–P3) | Файл:строки | Симптом | Корневая причина |
Влияние на пользователя | Доказательство (вывод команды) | Исправление |
Регрессионный тест
```

Дисциплина RED → GREEN: сначала тест, который падает на текущем коде и
показывает дефект, потом исправление, потом тот же тест зелёный. Вывод обеих
команд — в отчёт.

Коммиты маленькие и логически цельные.

## 7. Критерии приёмки — проверяемые, без прилагательных

Работа считается сделанной, когда все пункты подтверждены выводом команд:

1. `npm ci` — без ошибок.
2. `npm test` — все тесты зелёные, их **больше 50** (добавлено покрытие

3. `npm run build` — успешно.
4. `npm start` — **поднимает `server.mjs`**; все шесть эндпоинтов отвечают,

5. Каждая из шести функций раздела «Не работает» продемонстрирована рабочей:
   команда, ввод, вывод.
6. Debug APK собран; в отчёте — путь к файлу и результат установки.
7. Пять экранов на четырёх ширинах: ноль горизонтальных переполнений, ноль
   ошибок в консоли, скриншоты приложены.
8. `grep -rn "prefers-color-scheme: dark\|data-theme=.dark" src/` даёт ровно
   одно совпадение — комментарий `src/styles.css:5`, который констатирует
   отсутствие тёмной темы. Никаких новых совпадений появиться не должно.
9. В собранном бандле нет секретов: `grep -rE "sk-[A-Za-z0-9]{20,}" dist/` —
   пусто.
10. `git log origin/main..HEAD` — только коммиты в твоей ветке; `main` и

## 9. Продуктовое видение

Из `docs/PRODUCT_ARCHITECTURE.md`:

> NOTE2 — local-first блокнот и мультимодальное рабочее пространство
> доказательств, которое умеет принимать файлы и URL и производить анализ,
> подкреплённый provenance.

Стек: React 19, Vite 8, Node `server.mjs`, `pdfjs-dist`, Capacitor 8 для
Android, IndexedDB Source Vault, Docker + Render, FFmpeg/ffprobe на шлюзе.

Ключевой принцип: **всё сходится к одному контракту источника** —
provenance, метаданные, представления. Любой ответ AI обязан быть привязан к
фрагментам источников, а не сочинён.

Пять разделов навигации: **Сегодня · Заметки · Источники · Поиск · Профиль**.
